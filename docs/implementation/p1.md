## 2. OpenCode Integration Strategy — Fork vs. Plugin

This is **the most consequential decision**. Three approaches:

### Approach A: Fork OpenCode (Recommended for Neryva)

**What:** Fork `anomalyco/opencode`, modify the server to add governance hooks, multi-tenant session isolation, and custom tools.

**Why it's the right choice:**
- The governance layer needs to intercept **every message** in the agent loop — both inbound (user → LLM) and outbound (LLM → user). This requires hooks at `SessionPrompt.loop()` depth.
- Multi-tenancy requires the server to route sessions by tenant, isolate storage per tenant, and scope MCP connections per tenant. OpenCode's current server is single-project.
- You need custom system prompt injection (brand voice, rules) that is dynamic per-tenant, per-session. This requires changes in `packages/opencode/src/session/system.ts` and `packages/opencode/src/session/prompt.ts`.
- You need custom tool behavior: your "allow code tools only for specific domains" logic requires modifying the tool registry at `packages/opencode/src/tool/`.

**Fork boundary:**
```
neryva/
├── packages/
│   ├── opencode/          ← FORKED from anomalyco/opencode
│   │   ├── src/
│   │   │   ├── session/
│   │   │   │   ├── prompt.ts       ← MODIFIED: governance hooks
│   │   │   │   ├── system.ts       ← MODIFIED: dynamic brand injection
│   │   │   │   ├── processor.ts    ← MODIFIED: guardrail enforcement
│   │   │   │   └── governance.ts   ← NEW: governance intercept
│   │   │   ├── server/
│   │   │   │   ├── routes/
│   │   │   │   │   └── session.ts  ← MODIFIED: tenant-aware
│   │   │   │   └── middleware/
│   │   │   │       └── tenant.ts   ← NEW: tenant isolation
│   │   │   ├── agent/
│   │   │   │   └── agent.ts        ← MODIFIED: custom agents
│   │   │   └── tool/
│   │   │       └── registry.ts     ← MODIFIED: scoped permissions
│   ├── studio/             ← NEW: Neryva's web UI
│   ├── mcp-servers/        ← NEW: Neryva MCP fleet
│   └── governance-engine/  ← NEW: governance core
```

**Upstream merge strategy:** Pin to a release tag. Backport critical patches only. Do not attempt to stay on `main` — the upstream moves fast and your changes are deep.

### Approach B: Plugin System (Not sufficient for Neryva)

OpenCode's plugin system hooks (from `packages/plugin/`) are designed for extending tools and UI, not for modifying the core agent loop. The governance layer needs **compulsory middleware** that runs on every message — a plugin can be disabled; governance cannot.

### Approach C: Proxy Layer (Worse latency, less control)

A reverse proxy between OpenCode and the LLM could intercept messages for governance. But this loses access to internal state (session history, tool results, agent mode) that the governance engine needs. Also doubles latency.

**Decision: Fork. Accept the upstream merge cost. It's the only way to get the control you need.**

```
│  - Agent config →  per-tenant agents          │
│  - Filesystem   →  sandboxed path             │
└─────────────────────────────────────────────┘
```

**Why per-tenant processes instead of in-process multi-tenancy?**
- OpenCode's SQLite database is process-bound. Separate processes = separate databases = perfect isolation.
- One tenant's heavy session cannot starve another tenant.
- You can restart one tenant without affecting others.
- `opencode serve` already supports `--port` and `--data-dir` flags.

**Pool management:**
- Pre-warm a pool of 10-20 OpenCode servers
- Scale up/down based on demand
- Idle timeout: 15 minutes of inactivity → kill process
- Metrics: sessions/tenant, active/tenant

### 4.2 Implementation — Where to Hook OpenCode

The critical modification points in the forked `packages/opencode/src/session/`:

```typescript
// packages/opencode/src/session/prompt.ts
// MODIFIED: SessionPrompt.loop()

async function* loop(opts: LoopOptions): AsyncGenerator<AssistantMessage> {
  // ... existing OpenCode loop setup ...

  // === NERYVA HOOK 1: Pre-process user message ===
  const enrichedInput = await NeryvaGovernance.preProcess({
    input: userMessage,
    tenant: opts.tenantContext,
    session: opts.session,
  })

  // If governance decides to reject/redirect immediately
  if (enrichedInput.action === 'REJECT') {
    yield governanceRejection(enrichedInput.reason)
    return
  }
  if (enrichedInput.action === 'ESCALATE') {
    yield escalationRequest(enrichedInput.escalationReason)
    // Either wait for human response or continue with reduced scope
    const humanResponse = await waitForHumanInput(opts.session.id)
    enrichedInput.text = humanResponse.text
  }

  // === ORIGINAL OPENCODE LOOP ===
  // ... resolve tools, inject system reminders, LLM.stream() ...

  // === NERYVA HOOK 2: Intercept tool calls ===
  // In the tool-call processing section:
  for (const toolCall of toolCalls) {
    const allowed = await NeryvaGovernance.checkToolPermission({
      toolCall,
      tenant: opts.tenantContext,
      session: opts.session,
    })
    if (!allowed) {
      // Replace tool result with a governance block message
      toolCall.result = governanceBlockedResult(toolCall.name)
    }
  }

  // === NERYVA HOOK 3: Post-process LLM response ===
  const governanceResult = await NeryvaGovernance.postProcess({
    response: assistantMessage,
    tenant: opts.tenantContext,
    session: opts.session,
  })

  if (governanceResult.action === 'BLOCK') {
    yield governanceBlockedResponse(governanceResult.reason)
    return
  }

  if (governanceResult.action === 'ESCALATE') {
    yield governanceEscalatedResponse(assistantMessage, governanceResult.reason)
    // Session enters "pending human review" state
    await session.setStatus('pending_review')
    return
  }

  // Transform response if needed (brand overlay, format)
  yield governanceResult.transformedResponse ?? assistantMessage
}
```

```typescript
const server = new Server(

server.setRequestHandler(ListToolsRequestSchema, async () => ({

    name: 'neryva_search_knowledge',
    description: 'Search the tenant knowledge base for relevant information',
    inputSchema: {
      type: 'object',
      properties: {
        query: { type: 'string', description: 'The search query' },
        topK: { type: 'number', default: 5 },
        filterByTags: { type: 'array', items: { type: 'string' } },
      },
      required: ['query'],
    },
  }, {
    name: 'neryva_list_knowledge_sources',
    description: 'List available knowledge sources for this tenant',
    inputSchema: { type: 'object', properties: {} },
  }]
}))

server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === 'neryva_search_knowledge') {
    const { query, topK = 5 } = request.params.arguments!
    const tenantId = request.session?.tenantId  // from MCP session context

    // Vector search
    const embedding = await embed(query)
    const results = await qdrant.search(tenantId, {
      vector: embedding,
      limit: topK,
      with_payload: true,
    })

    // Hybrid: also do BM25 keyword search, merge results
    // Rerank using cross-encoder

    return {
      content: [{
        type: 'text',
        text: formatResults(results),
      }],
    }
  }
})
```

Agent creation flow:
1. Admin configures agent via Studio UI
2. Studio writes agent config to Postgres
3. Studio calls `POST /tenant/{id}/agents/{id}/deploy`

## 8. Session Lifecycle Detail

```
1. USER SENDS MESSAGE
   │
2. API Gateway receives POST /api/v1/sessions/{id}/prompt
   → Validates JWT, extracts tenant
   → Routes to tenant's OpenCode server
   → POST /session/{id}/prompt
   │
3. OpenCode Server receives
   → NERYVA HOOK: preProcessGovernance(input)
     → Topic check, PII mask, rate limit
     → If BLOCK: return immediately
     → If ESCALATE: create human handoff task
   │
4. SessionPrompt.loop() begins
   → System prompt = base + brand voice + rules + knowledge context
   → Tool set filtered by tenant permissions
   → LLM.stream() → SSE events streamed back to user
   │
5. During loop, tool calls invoke MCP servers
   → neryva-knowledge for RAG
   → neryva-crm for customer data
   → neryva-ticketing for ticket ops
   │
6. NERYVA HOOK: postProcessGovernance(output)
   → Brand compliance check
   → Hallucination detection
   → Policy verification
   → Escalation decision
   │
7. Response sent to user (or escalated)
   → Agent message over SSE
   → If escalated: human receives notification
```

## 11. Security Architecture

### 11.1 Threat Model

```
Threat                    Mitigation
────────────────────────────────────────────────────────────────────
Tenant data leakage       Per-tenant OpenCode processes + SQLite DBs
                          Tenant ID in every MCP request
                          All PII masked at input guardrail layer
                          
Prompt injection          Input guardrails detect and block
                          Tool permissions scoped per agent
                          Output guardrails catch injection in responses

                          Permission system: ask before dangerous tools
                          Code tools disabled for customer-facing agents

                          Keys never logged
                          Per-tenant API keys with scoped permissions
                          
Data exfiltration         Output guardrails check for sensitive data
                          Rate limits per session
                          Audit log of all tool invocations
                          
Supply chain              Pin OpenCode fork to release tags
                          MCP server integrity checks at startup
                          SBOM generation per deployment
```

### 12.2 OpenCode Pool Management

```typescript
// packages/opencode/src/server/pool.ts (NEW)
class OpenCodePool {
  private pool: Map<string, {
    process: ChildProcess
    port: number
    agentConfig: NeryvaAgentConfig
    lastActivity: number
    metrics: PoolMetrics
  }>

  async acquire(tenantId: string): Promise<ServerHandle> {
    // Check if tenant already has a running server
    let server = this.pool.get(tenantId)
    if (server && server.process.exitCode !== null) {
      // Process died, restart
      server = await this.startServer(tenantId)
    }
    if (!server) {
      server = await this.startServer(tenantId)
    }
    server.lastActivity = Date.now()
    return { port: server.port, host: 'localhost' }
  }

  private async startServer(tenantId: string) {
    const port = await this.findAvailablePort(4000, 5000)
    const dataDir = `/data/tenants/${tenantId}`
    
    const proc = Bun.spawn([
      'opencode', 'serve',
      '--port', String(port),
      '--data-dir', dataDir,
      '--hostname', '127.0.0.1',
    ], {
      env: {
        ...process.env,
        NERYVA_TENANT_ID: tenantId,
        NERYVA_API_KEY: await this.getTenantApiKey(tenantId),
      }
    })

    await this.waitForHealth(port, 30_000)  // 30s timeout
    
    return { process: proc, port, metrics: { sessions: 0 } }
  }

  async release(tenantId: string) {
    // Called after 15 minutes of inactivity
    const server = this.pool.get(tenantId)
    if (server) {
      server.process.kill('SIGTERM')
      setTimeout(() => server.process.kill('SIGKILL'), 10_000)
      this.pool.delete(tenantId)
    }
  }
}
```

## 14. Critical Risks & Mitigations

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| **OpenCode upstream moves fast, fork falls behind** | High | Medium | Pin to stable releases. Backport only security patches. Accept that you're essentially running a separate project. |
| **LLM cost explosion per tenant** | Medium | High | Per-tenant cost caps. Hard stop at $X/day. Model tiering (cheap model for simple queries, expensive for complex). |
| **Prompt injection bypasses guardrails** | Medium | Critical | Layered defense: pre-check, in-prompt constraints, post-check. All three must agree. MCP tool calls also checked. |
| **Tenant isolation failure** | Low | Critical | Process-level isolation. Each tenant is a separate OS process. If one crashes, others unaffected. |
| **OpenCode process crash during session** | Medium | Medium | Session state is written to SQLite on each step. On restart, session resumes from last persisted state. MCP idempotency for tool calls. |
| **Knowledge RAG returns irrelevant context** | High | Medium | Reranker (cross-encoder) as second pass. Guardrail confidence check on retrieved context. If low confidence, agent must ask clarifying question. |
| **Human escalations pile up** | Medium | High | Auto-escalation timeout (if
